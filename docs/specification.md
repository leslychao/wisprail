# Wisprail: JavaFX и sing-box

Канонические требования первого выпуска, обновлённые 13 октября 2026 года.
Дизайн: [specification.md](design/specification.md). HTML и PNG — ориентиры интерфейса,
а не доказательство реализации. Готовность Windows и macOS подтверждается отдельно.

## Назначение и границы

Приложение хранит несколько VPN-профилей. На компьютере активен один профиль.
VLESS поддерживает режим «Весь интернет»: IPv4, IPv6 и DNS идут через VPN.
Импорт VLESS-ссылки выбирает этот режим и позволяет сохранить профиль и подключиться
без ручного заполнения сетей и корпоративного DNS. OpenVPN и выборочный режим VLESS
направляют через VPN явно выбранные IPv4-сети и корпоративные DNS-запросы;
непрофильные адреса сохраняют существующий системный путь, в том числе через другой VPN.
Автоматическое переключение профилей, автоматический откат после неудачного переключения
и kill switch не входят в выпуск.

Поддерживаются Windows 10/11 x64 и macOS 13+ на Intel и Apple Silicon,
OpenVPN и VLESS TCP или gRPC с TLS или Reality.
WebSocket, ручные IPv6-сети профиля и неизвестные значимые параметры импорта
отклоняются с объяснением. Выборочный режим не перенастраивает системный IPv6;
приложения со своим DoH и IPv6-трафик находятся вне гарантии системного split DNS.
В полном режиме sing-box создаёт маршруты обоих семейств адресов и обслуживает системный DNS;
запросы приложений со своим DoH также идут через туннель как обычный интернет-трафик.

## Процессы и владельцы

```text
JavaFX, обычный пользователь
    ↕ защищённый named pipe / Unix domain socket
Java-служба управления, системные права
    ↕ запуск, проверка, остановка, API готовности
sing-box 1.14.2
    ↕ TUN, маршруты, OpenVPN/VLESS
VPN-сервер
```

Стек: Java 21, JavaFX 21, Maven Wrapper. Два Maven-модуля: `core/` и `desktop/`.
Платформенная упаковка находится в `packaging/`. Spring, HTTP-бэкенд и БД не нужны.

Mac-дистрибутивы разрешено собирать на Linux через OSXCross и официальный Apple SDK.
Кросс-сборка сохраняет Java 21, JavaFX, структуру `.app`, комплектный runtime и штатную
установку привилегированного компонента. Обычные ZIP используют локальную ad-hoc подпись;
Developer ID и notarization остаются отдельным режимом выпуска. Проверки структуры,
архитектуры и подписи при сборке не заменяют запуск и системную приёмку на macOS.
Движок поставляется вместе с приложением, его версия и контрольная сумма фиксированы.
Автоматического обновления движка нет. Конфигурация и API привязаны к исходникам 1.14.2.

JavaFX владеет редактором, выбранным профилем, пользовательским хранилищем и представлением.
`ConnectionService` в службе — единственный владелец запуска, переключения, отмены и очистки.
Служба получает типизированный профиль, проверяет его и самостоятельно собирает конфигурацию.
Произвольные команды, пути исполняемых файлов и пользовательский sing-box JSON через IPC запрещены.
Канал проверяет пользователя и системного владельца службы, допускает одну UI-сессию.

sing-box владеет протоколами, одним TUN и маршрутами. Java-служба владеет только собственными
объектами системного split DNS в выборочном режиме: NRPT на Windows и SystemConfiguration
`SupplementalMatchDomains` на macOS. В полном режиме системным DNS владеет TUN sing-box.
UI не меняет системную сеть и не получает системный пароль.
Установка службы и разрешения выполняются штатными средствами ОС: Windows Service/UAC,
LaunchDaemon/SMAppService на macOS.

На Windows перед открытием основного окна UI проверяет службу. Отсутствующий компонент
подготавливается из комплектного дистрибутива в Program Files через UAC; остановленная
служба запускается тем же штатным механизмом. Работающая служба не требует повышения прав.
Подготовка выполняется вне JavaFX-потока и завершается до создания IPC-клиента.
При отмене или ошибке профили остаются доступны, а экран показывает причину и переход
к настройкам компонента. Успешная повторная подготовка обновляет IPC-сессию без перезапуска UI.
Клиент ограниченно повторяет получение состояния после разрыва, но не повторяет сетевые команды.

## Профиль и хранение

Неизменяемый профиль содержит ID, ревизию, название, сервер, порт, настройки одного протокола,
IPv4 CIDR, IPv4 корпоративного DNS, доменные суффиксы, необязательный HTTPS-ресурс проверки
и ссылку на секреты. Сохранённая ревизия и фактически применённый снимок различаются.
Переименование не требует переподключения. Сетевые изменения активного профиля можно сохранить
на потом; карточка активного VPN продолжает показывать применённые настройки.

Профили — версионируемый JSON, атомарная запись с проверкой ревизии. Секреты — DPAPI пользователя
Windows или Keychain macOS. Временная конфигурация доступна службе и удаляется после остановки.
Пароли, UUID VLESS, закрытые ключи и полные конфиги не попадают в журнал и отчёты.
Экспорт и копирование исключают секреты. Неполный импорт остаётся несохранённым черновиком.

Импорт `.ovpn`, Wisprail JSON и VLESS-ссылки проходит через предпросмотр.
Известные параметры преобразуются явно. Скрипты, неизвестные значимые директивы,
неподдержанные транспорты и небезопасные ссылки на файлы блокируют импорт.

Для VLESS gRPC сохраняется `serviceName`, включая пустую строку; в конфигурации
движка это `transport.type=grpc` и `transport.service_name`. Непустой `authority`
отклоняется, поскольку комплектный движок не поддерживает его переопределение.
`flow=xtls-rprx-vision` допустим только для TCP. Параметр Reality `spx` относится
к маскирующему обходу сайта [Xray](https://github.com/XTLS/Xray-core/blob/main/transport/internet/reality/reality.go)
после неудачной авторизации: sing-box его не
использует. Импорт предупреждает об этом в предпросмотре, не меняя параметры
VPN-подключения. Существующие JSON-профили без транспорта читаются как TCP.
Схема транспорта соответствует [sing-box 1.14.2](https://github.com/SagerNet/sing-box/blob/v1.14.2/option/v2ray_transport.go).

## Сети и DNS

Выборочный режим использует явные IPv4 CIDR; совокупность сетей с полным охватом запрещена.
Единственный канонический признак полного режима — список сетей `["0.0.0.0/0"]` у VLESS,
распознаваемый `Profile.fullTunnel()`. Формат сохранённых профилей не меняется.
Генератор создаёт IPv4- и IPv6-маршруты по умолчанию с исключением IPv4-адресов VPN-сервера.
DNS в полном режиме работает через TUN, по умолчанию используется `1.1.1.1` через VLESS;
прямого DNS fallback нет. Обычные маршруты локальной сети не считаются конфликтом полного
режима; служебные адреса TUN проверяются на пересечения. Чужие маршруты `/1` блокируют
полное подключение, чтобы не перезаписать другой VPN. IPv6 использует два `/1`, сохраняя
системный маршрут по умолчанию. Более специфичные внешние статические маршруты продолжают
подчиняться правилам приоритета маршрутов ОС.
OpenVPN работает во внутреннем сетевом стеке: серверные маршруты, DNS и `redirect-gateway`
не подменяют настройки профиля. Путь до VPN-сервера остаётся вне собственного TUN.

В выборочном режиме для выбранных доменов ОС обращается к DNS-входу sing-box на служебном TUN-адресе.
sing-box отправляет запрос корпоративному DNS через VPN. Остальные домены продолжают
использовать прежние настройки ОС. Глобальный DNS-перехват не применяется.
Ошибка корпоративного DNS не разрешает fallback на публичный DNS.
Совпадение домена проверяется по границе суффикса: `corp.example` и `a.corp.example`
совпадают, `evilcorp.example` — нет. Если DNS вне сетей, пользователь явно добавляет его `/32`.

Конфликтующие маршруты, правила другого VPN и управляемая политика ОС блокируют применение.
Чужие настройки не перезаписываются. `.local`, кэш DNS, смена сети, сон и пробуждение
проверяются на обеих ОС отдельно; синтаксическая проверка не доказывает сетевую совместимость.

## Жизненный цикл

1. Проверить профиль, секреты, компонент и системные конфликты.
2. Собрать кандидат и выполнить настоящий `sing-box check`, сохраняя работающий VPN.
3. При переключении получить подтверждение, связанное с кандидатом и ревизией подключения.
4. Остановить прежний VPN и подтвердить очистку его процесса, маршрутов и DNS.
5. Запустить новый экземпляр, установить собственные доменные правила и проверить готовность.
6. Опубликовать применённый снимок и `CONNECTED`.

Ограничение «один sing-box» относится к работающему VPN. Короткий `check` не создаёт подключения.
Ошибка предварительной проверки оставляет прежний VPN. Неудача после его остановки даёт ERROR
без автоматического возврата. Отмена и поздние события связаны с идентификатором операции.
Состояния: DISCONNECTED, CONNECTING, CONNECTED, DISCONNECTING, ERROR; подготовка кандидата
показывается отдельно и может идти при CONNECTED.

OpenVPN подтверждает готовность событиями endpoint из API движка. Выборочный VLESS требует
настоящего ответа корпоративного DNS либо явно заданного HTTPS-ресурса внутри выбранных
IPv4-сетей, без публичного адреса проверки по умолчанию. Полный VLESS проверяется DNS-запросом
через DNS-вход TUN и публичный resolver через VLESS. Непустой HTTPS-ресурс остаётся явно
заданной альтернативой. Наличие процесса, TCP-порта и корректного JSON не означает CONNECTED.
Проверка конкретного ресурса — отдельная диагностическая операция.

Служба сохраняет принадлежность процесса и DNS-объектов, следит за UI и движком.
При выходе UI VPN останавливается; скрытие в трей сохраняет UI-процесс.
После аварии удаляются только собственные остатки. Неподтверждённая очистка даёт ERROR,
блокирует новый запуск и требует повторной проверки. Блокировка трафика после падения не гарантируется.

## Интерфейс

Три раздела: подключения, журнал, настройки. Общий редактор с четырьмя вкладками:
основное, доступ, сети, DNS. Выбранный, редактируемый и активный профили независимы.
Предусмотрены импорт, экспорт, копирование, удаление, отложенное применение,
диагностика и отчёты, трей, уведомления и настройки запуска.
Стандартные JavaFX-контролы и общий CSS; файловые и сетевые операции вне FX thread.
Журнал ограничен и обновляется пакетами. Трей получает тот же снимок, что окно.
Клавиатура, видимый фокус, длинные русские подписи и масштабирование обязательны.

## Критерии завершения

- Валидаторы: CIDR, полный охват несколькими сетями, доменные границы, строгий импорт.
- Жизненный цикл: повторный клик, отмена, поздние события, переключение, ошибка кандидата,
  сохранённая и применённая ревизии, отказ в правах/credentials, падение каждого процесса,
  ошибка очистки и повторный запуск.
- Реальные запросы обычного приложения: профильный IP через VPN, непрофильный прежним путём,
  корпоративный DNS через заданный сервер. Соседний VPN, смена сети, сон и пробуждение.
- Полный VLESS: импорт ссылки, сохранение и подключение без ручных сетей и DNS,
  IPv4/IPv6 и системный DNS через VPN, отказ при недоступном сервере, очистка обоих семейств маршрутов.
- Все 41 состояния дизайна, клавиатура и масштабирование.
- Отсутствие секретов в JSON профиля, логах, экспорте и диагностических отчётах.
- Установщики со своим runtime, установка, обновление и удаление. Windows EXE собираются
  через jpackage без личного сертификата: собственные компоненты остаются неподписанными,
  имеющиеся подписи поставщиков сохраняются. Ограничения Windows на запуск не обходятся.
  Для macOS в обычной сборке применяется ad-hoc подпись; Developer ID и notarization
  остаются отдельным режимом выпуска.

Сборка и unit-тесты подтверждают только проверенные ими свойства. Приёмка Windows/macOS,
сетевые маршруты, подпись и установщики отмечаются отдельными результатами.
